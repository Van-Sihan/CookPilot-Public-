입력을 받아 처리하기까지 — 키보드에서 저장까지

물어본 것 — “데이터 입력을 어떻게 받아와서 그걸 처리하는지 흐름을 알고 싶어.”

02번 문서가 값이 어느 파일을 거쳐 가는지를 다뤘다면, 이 문서는 그 앞쪽 — 사용자가 친 글자가 애초에 어떻게 코드 안으로 들어오는지를 다룹니다. 키보드를 누르는 순간부터 따라갑니다.

1부 · 기본 문법

React 에서 입력칸은 값을 들고 있지 않습니다

여기가 처음 배울 때 가장 이상하게 느껴지는 부분입니다.

보통 HTML 입력칸은 자기가 값을 들고 있습니다. 사용자가 글자를 치면 입력칸 안에 그 글자가 쌓입니다. 코드는 필요할 때 “거기 뭐라고 적혀 있어?” 하고 물어봅니다.

<!-- 그냥 HTML -->
<input id="key">

<script>
  // 필요할 때 입력칸에게 물어본다
  const 값 = document.getElementById("key").value;
</script>

React 는 반대입니다. 값은 React 가 들고 있고, 입력칸은 그것을 비춰 보여 주기만 합니다. 거울이라고 생각하면 됩니다.

const [값, 값바꾸기] = useState("");

<input value={값} onChange={...} />
//     ↑ 거울에 비출 대상
알아두면 좋은 것 — 왜 이렇게 하나

값이 한 군데에 모여 있으면 “지금 무엇이 입력되어 있는가”를 한 곳만 보면 됩니다. 입력칸이 열 개여도 마찬가지입니다. 또 값을 코드로 바꾸면(예: 저장 후 비우기) 화면이 알아서 따라옵니다. 입력칸에게 일일이 “너 비워라” 라고 시키지 않아도 됩니다.

useState — 값을 기억하는 상자

useState 는 화면을 다시 그려도 값이 살아남게 해 주는 도구입니다.

const [raw, setRaw] = useState("");
//      ↑     ↑                ↑
//   지금 값  바꾸는 함수    처음 값

왼쪽 대괄호는 두 개짜리 배열을 한 번에 풀어 받는 문법입니다. useState 가 [값, 바꾸는함수] 를 돌려주므로 이렇게 받습니다.

헷갈리기 쉬운 점

값을 직접 바꾸면 안 됩니다. 반드시 바꾸는 함수를 써야 합니다.

raw = "AIza";        // ✗ 화면이 안 바뀜 (게다가 const 라 에러)
setRaw("AIza");      // ✓ React 가 알아채고 화면을 다시 그림

React 는 이 함수가 불린 것을 보고 “값이 바뀌었으니 화면을 새로 그려야겠다” 고 판단합니다. 직접 대입하면 아무도 모릅니다.

이벤트 — 브라우저가 알려 주는 “방금 이런 일이 있었다”

사용자가 무언가 하면 브라우저가 이벤트를 일으킵니다. 우리는 “그 일이 생기면 이 함수를 불러 달라” 고 미리 맡겨 둡니다.

<input onChange={함수} />      글자가 바뀌면 이 함수를 불러 줘
<form onSubmit={함수} />       제출되면 이 함수를 불러 줘
<button onClick={함수} />      눌리면 이 함수를 불러 줘

불릴 때 그 함수는 무슨 일이 있었는지 적힌 쪽지를 하나 받습니다. 보통 e 라고 이름 짓습니다 (event 의 첫 글자).

2부 · 우리 코드에서는

준비 · 값을 담을 상자 세 개

components/start/api-key-form.tsx:24 
const [raw, setRaw] = useState("");                      // 입력칸에 적힌 글자
const [shown, setShown] = useState(false);               // 키를 눈에 보이게 할지
const [message, setMessage] = useState<string | null>(null);  // 오류 문구

세 개가 각각 화면의 한 부분을 맡습니다. raw 는 입력칸, shown 은 눈 모양 단추, message 는 입력칸 밑의 빨간 글씨입니다.

걸음 1 · 글자 하나마다 한 바퀴 돈다

components/start/api-key-form.tsx:122 
<input
  value={raw}
  onChange={(e) => {
    setRaw(e.target.value);
    setMessage(null);
  }}
  ...
/>

AIza 네 글자를 치면 이 고리가 네 번 돕니다.

사용자가 'A' 를 누름
    ↓
브라우저가 onChange 이벤트를 일으킴
    ↓
(e) => setRaw(e.target.value)          e.target.value 는 "A"
    ↓
raw 가 "" 에서 "A" 로 바뀜
    ↓
React 가 ApiKeyForm 함수를 처음부터 다시 실행
    ↓
<input value={raw} /> 가 value="A" 로 다시 그려짐
    ↓
화면에 'A' 가 보인다

여기서 e.target 은 이벤트가 일어난 그 입력칸, .value 는 지금 거기 적혀 있는 글자 전부입니다. 방금 친 한 글자가 아닙니다.

'A' 치면  → e.target.value = "A"
'I' 치면  → e.target.value = "AI"
'z' 치면  → e.target.value = "AIz"
'a' 치면  → e.target.value = "AIza"
알아두면 좋은 것

붙여넣기(Ctrl+V)도 똑같이 onChange 한 번으로 처리됩니다. 39글자를 한꺼번에 붙여넣으면 e.target.value 에 39글자가 통째로 들어옵니다. 글자 수만큼 도는 것이 아니라 “값이 바뀔 때마다” 도는 것이기 때문입니다.

같은 자리에 setMessage(null) 이 함께 있는 이유도 여기 있습니다. 다시 타이핑을 시작하면 아까 뜬 오류 문구를 치우는 것입니다. 틀렸다는 빨간 글씨를 보면서 고치는 중인데 그 글씨가 계속 남아 있으면 거슬리기 때문입니다.

걸음 2 · 단추를 누르면 폼이 제출된다

components/start/api-key-form.tsx:111 
<form onSubmit={onSubmit} noValidate>
  ...
  <button className="btn btn-fill start-go" type="submit">
    들어가기
  </button>
</form>

type="submit" 인 단추를 누르면 감싸고 있는 <form> 의 onSubmit 이 불립니다.

입력칸에서 Enter 를 눌러도 똑같이 불립니다. 이건 우리가 따로 만든 게 아니라 브라우저가 원래 해 주는 일입니다. 그래서 마우스를 쓰지 않고도 키를 붙여넣고 바로 Enter 로 넘어갈 수 있습니다.

걸음 3 · 새로고침을 막는 한 줄

components/start/api-key-form.tsx:49 
function onSubmit(e: React.FormEvent<HTMLFormElement>) {
  e.preventDefault();
  ...

폼이 제출되면 브라우저는 원래 하던 일을 하려고 합니다 — 적힌 값을 주소에 붙여 서버로 보내고 페이지를 새로 불러오는 것입니다. 아주 옛날 웹의 방식입니다.

지금은 그럴 필요가 없습니다. 우리가 직접 처리할 거니까요. e.preventDefault() 가 “원래 하던 일은 하지 마” 라고 막는 한 줄입니다.

헷갈리기 쉬운 점

이 줄을 빼면 화면이 깜빡이며 처음부터 다시 로딩됩니다. 우리가 저장한 것도, 띄우려던 오류 문구도 다 날아갑니다. “단추를 눌렀는데 화면이 새로고침되고 아무 일도 안 일어난다” 면 십중팔구 이 줄을 빠뜨린 것입니다.

걸음 4 · 처리는 통째로 넘긴다

components/start/api-key-form.tsx:54 
const result = enterWithApiKey(raw, browserApiKeyStore);
//                              ↑          ↑
//                     지금까지 모인 값   저장할 곳

화면의 일은 여기서 끝납니다. 검사도 저장도 직접 하지 않습니다. 그 안에서 무슨 일이 벌어지는지는 02번 문서에서 다뤘습니다.

화면이 아는 것은 두 가지뿐입니다 — 무엇을 넘길지, 그리고 결과를 받아 무엇을 보여 줄지.

걸음 5 · 결과를 받아 화면을 정한다

components/start/api-key-form.tsx:56 
if (!result.ok) {
  setMessage(apiKeyMessages[result.reason]);   // 실패 → 문구 띄우고
  return;                                      //        여기서 끝
}

setMessage(null);   // 성공 → 오류 문구 치우고
setRaw("");         //        입력칸 비우고
                    //        ... 카드를 바꾸는 코드는 없다

apiKeyMessages[result.reason] 는 이유를 사람이 읽을 문구로 바꾸는 부분입니다. 대괄호로 꺼내는 이유는 result.reason 값이 그때그때 다르기 때문입니다.

result.reason 이 "empty" 이면
    apiKeyMessages["empty"]  →  "키를 붙여넣어 주세요."

result.reason 이 "storage" 이면
    apiKeyMessages["storage"] →  "브라우저가 저장을 막고 있습니다. ..."

도메인은 "empty" 라는 이유만 알려 주고, 사람에게 보여 줄 말은 화면이 정합니다. 그래서 문구를 고칠 때 lib/domain 을 건드릴 일이 없습니다.

성공했는데 왜 카드를 바꾸는 코드가 없나

성공 쪽을 보면 이상합니다. 오류 문구를 치우고 입력칸을 비우기만 할 뿐, “이제 들어와 있습니다 화면을 보여 줘” 라는 코드가 없습니다.

일부러 없는 것입니다. 저장하는 순간 어댑터가 “값이 바뀌었다” 고 알리고, 그 알림을 듣고 있던 React 가 알아서 다시 그립니다.

store.save(키)  →  localStorage 에 쓰기  →  notify()
                                              ↓
                              구독 중이던 화면이 다시 그려짐
                                              ↓
                          hasSaved 가 true 가 되어 카드가 교체됨

이 구조 덕분에 화면이 여러 개여도 전부 같이 바뀝니다. 각 화면마다 “너도 바꿔라” 라고 시킬 필요가 없습니다. 자세한 것은 02번 문서의 “저장하면 화면이 저절로 바뀌는 이유” 절에 있습니다.

전체를 한 장으로

[입력]
  키보드 → onChange → setRaw() → raw 에 쌓임
                                   (값이 바뀔 때마다 반복)
[제출]
  단추 또는 Enter → onSubmit → e.preventDefault()
                                   ↓
[처리]                    enterWithApiKey(raw, store)
                                   ↓
                             checkApiKey()      규칙
                                   ↓
                             store.save()       저장
                                   ↓
                               notify()
[반영]                             ↓
                     구독 중이던 화면이 다시 그려짐
                                   ↓
                       "들어와 있습니다" 카드로 교체

3부 · 직접 확인해보기

실험 1 · 글자마다 한 바퀴 도는 것을 눈으로 보기

components/start/api-key-form.tsx 의 onChange 에 한 줄을 넣으세요.

onChange={(e) => {
  console.log("지금 raw:", e.target.value);   // ← 추가
  setRaw(e.target.value);
  setMessage(null);
}}

/start 를 열고 F12 → Console 탭을 켠 뒤 입력칸에 AIza 를 천천히 쳐 보세요. 로그가 네 줄 쌓이고, 글자가 하나씩 늘어나는 것이 보입니다.

이번엔 아무 글자나 붙여넣기 해 보세요. 로그가 한 줄만 뜹니다. 확인했으면 지우세요.

실험 2 · 거울을 깨 보기

value={raw} 를 통째로 지워 보세요.

<input
  value={raw}      ← 이 줄을 지운다
  onChange={...}

글자는 여전히 쳐집니다. 하지만 “들어가기”를 눌러도 아무 일도 일어나지 않습니다. 화면에는 글자가 보이는데 raw 는 빈 문자열이라 “키를 붙여넣어 주세요” 가 뜹니다.

입력칸에 보이는 글자와 코드가 들고 있는 값이 따로 놀게 된 것입니다. 이게 value={raw} 가 하던 일입니다. 되돌리세요.

실험 3 · 새로고침 막는 줄을 빼 보기

onSubmit 의 e.preventDefault(); 를 주석 처리하고 “들어가기” 를 눌러 보세요.

화면이 깜빡이며 새로고침됩니다. 주소창을 보시면 ? 가 붙어 있을 수도 있습니다 — 브라우저가 입력값을 주소에 붙여 서버로 보내려 한 흔적입니다. 되돌리세요.

실험 4 · 오류 문구가 언제 사라지는지

입력칸을 비운 채 “들어가기” 를 눌러 오류 문구를 띄우세요. 그 다음 아무 글자나 한 자 쳐 보세요.

문구가 즉시 사라집니다. onChange 안의 setMessage(null) 이 한 일입니다. 그 줄을 잠깐 지우면 글자를 쳐도 빨간 글씨가 계속 남아 있는 것을 볼 수 있습니다.

헷갈리기 쉬운 점 — “다시 그린다”는 게 무슨 뜻인가

글자를 칠 때마다 ApiKeyForm 함수가 처음부터 끝까지 다시 실행됩니다. 그런데도 raw 값이 초기화되지 않습니다. useState("") 의 "" 는 맨 처음 한 번만 쓰이고, 그 뒤로는 React 가 기억해 둔 값을 돌려주기 때문입니다.

또 하나 — “다시 그린다” 는 것이 화면을 통째로 지우고 새로 만든다는 뜻은 아닙니다. React 는 바뀐 곳만 골라 고칩니다. 그래서 글자를 쳐도 입력칸의 커서 위치가 유지됩니다.
