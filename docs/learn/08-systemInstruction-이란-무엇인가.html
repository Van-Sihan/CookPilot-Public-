쿡파일럿 학습 노트 · 08

systemInstruction 이란 무엇인가

물어본 것 — “systemInstruction 이 뭐야?”

AI에게 대화가 시작되기 전에 미리 건네는 지시문입니다. 이 문서를 다 읽고 나면 사용자가 하는 말과 무엇이 다른지, 쿡파일럿이 요리 도우미에게 실제로 무슨 말을 미리 해 두는지, 그리고 왜 레시피를 통째로 거기 넣었는지 알게 됩니다. lib/usecase/cook-along.ts 와 lib/adapter/gemini-live-gateway.ts 를 읽습니다.

1부 · 기본 문법

대화에는 세 가지 역할이 있습니다

AI와 주고받는 말에는 역할(role)이 붙습니다. 누가 한 말인지 표시하는 이름표입니다.

  • system : 개발자가 미리 정해 두는 지시. 사용자에게는 안 보입니다.
  • user : 사용자가 실제로 한 말
  • assistant (또는 model) : AI가 한 대답

systemInstruction 은 이 중 system 자리에 들어가는 글입니다. "너는 이런 역할이고, 이런 규칙을 지켜라" 를 미리 적어 두는 자리입니다.

가장 작은 예제

// 지시문 없이 그냥 물으면
"오늘 뭐 먹지?"
→ AI가 아무 말이나 길게 늘어놓는다

// 지시문을 미리 건네면
system: "너는 한식만 추천한다. 한 문장으로만 답한다."
user:   "오늘 뭐 먹지?"
→ "된장찌개 어떠세요?"

같은 질문인데 답이 달라졌습니다. 지시문이 답의 모양을 미리 정해 둔 것입니다.

지시문은 한 번만 보냅니다. 대화가 열 번 스무 번 오가도 다시 보내지 않습니다. 모델이 그 대화 내내 기억하고 있기 때문입니다.

user 메시지에 적으면 안 되나요

적어도 동작은 합니다. 그런데 두 가지가 나빠집니다.

첫째, 사용자에게 보입니다. 화면에 대화 내용을 그리면 "너는 요리 도우미다…" 가 사용자 말풍선으로 뜹니다.

둘째, 모델이 덜 무겁게 받아들입니다. system 자리에 있는 글은 사용자가 뭐라고 하든 잘 지키려 합니다. user 자리에 있으면 뒤에 오는 말에 밀려 잊히기 쉽습니다.

2부 · 우리 코드에서는

쿡파일럿의 요리 도우미는 말로만 대화합니다. 화면을 못 보는 사람에게 말하는 것이라 규칙이 특히 많이 필요합니다. 그 규칙이 전부 systemInstruction 에 들어 있습니다.

지시문을 만드는 곳

lib/usecase/cook-along.ts:88

export function cookingBrief(brief: CookBrief): string {
  const { recipe, tone } = brief;

  // 재료를 한 줄씩 늘어놓는다
  const ingredients = recipe.ingredients
    .map((i) => `- ${i.name} ${i.amount}`)
    .join("\n");

  // 걸음마다 번호를 붙인다.
  // 번호가 있어야 "3번째 걸음" 이라고 주고받을 수 있다
  const steps = recipe.steps
    .map((s, i) => `${i + 1}. ${s.text}${s.minutes ? ` (${s.minutes}분)` : ""}`)
    .join("\n");

재료와 순서를 글자로 늘어놓는 것이 먼저입니다. 모델은 자바스크립트 객체를 모릅니다. 글로 적어 줘야 읽습니다.

실제로 건네는 규칙

이어지는 부분이 이 파일의 핵심입니다. 규칙 하나하나에 이유가 있습니다.

lib/usecase/cook-along.ts:105

  return [
    "너는 요리하는 사람 옆에 서 있는 요리 도우미다.",
    toneAsk[tone],
    "",
    "규칙:",
    "- 한 번에 한두 문장으로만 답한다. 길게 설명하지 않는다.",
    "- 상대는 손이 젖어 있고 화면을 못 본다. 숫자와 시간은 또렷하게 말한다.",
    "- 모르는 것은 지어내지 않고 모른다고 한다.",
    "- 레시피에 없는 것을 물으면 일반적인 요리 상식으로 짧게 답한다.",

세 번째 줄이 이 서비스의 사정입니다. 일반 챗봇이라면 필요 없는 문장인데, 귀로만 듣는 상황이라 "3분" 같은 숫자를 흘리듯 말하면 못 알아듣습니다.

다음 세 줄은 실제로 겪은 문제를 막으려고 넣은 것입니다.

lib/usecase/cook-along.ts:116

    "- 자기에게 한 말이 아닌 것 같으면 아무 말도 하지 않는다.",
    "- '다음', '이전', '다시' 는 화면을 넘기라는 신호일 뿐이다.
       절대 대답하지 마라. 아무 소리도 내지 마라.",
    "- [읽기] 로 시작하는 말을 받으면, 따옴표 안의 문장만 그대로 읽는다.
       한 글자도 바꾸지 말고, 앞뒤에 아무 말도 붙이지 마라.",

왜 이런 규칙이 필요했는지는 코드 주석에 적혀 있습니다.

  • 마이크가 내내 켜져 있어서 부엌 소리와 혼잣말이 그대로 들어옵니다. 그때마다 대꾸하면 성가시다 못해 안내를 못 듣습니다.
  • "다음" 은 화면이 알아듣고 걸음을 옮깁니다. 모델까지 따로 대꾸하면 "네, 다음 단계는…" 과 걸음 읽기가 겹쳐 두 번 말합니다.
  • [읽기] 는 화면이 모델에게 "이 문장을 소리로 내 달라" 고 보내는 신호입니다. 여기에 "타이머를 걸까요?" 같은 말을 덧붙이면 묻지 않은 말을 하게 됩니다.

지시문은 처음부터 이렇게 길지 않았을 것입니다. 모델이 원하지 않는 행동을 할 때마다 한 줄씩 붙여 나간 결과입니다. 프롬프트를 다듬는 일이 대체로 이렇게 생겼습니다.

레시피를 통째로 넣는 까닭

lib/usecase/cook-along.ts:123

    `지금 만드는 요리: ${recipe.title} (${recipe.servings}인분)`,
    "",
    "재료:",
    ingredients,
    "",
    "순서:",
    steps,
  ].join("\n");

레시피 전체가 지시문 안에 들어갑니다. 파일 위쪽 주석이 그 까닭을 밝혀 둡니다 — 걸음마다 다시 알려 주면 그때마다 토큰을 더 쓰기 때문입니다.

더 중요한 것이 있습니다. 레시피를 통째로 알고 있어야 "다음에 뭐 하지?", "소금 얼마나 넣어?" 같은 물음에 답할 수 있습니다. 지금 걸음만 알려 주면 그 질문에 "모르겠다" 고 답하게 됩니다.

웹소켓에 실려 나가는 자리

만든 글자는 세션을 열 때 딱 한 번 실려 나갑니다.

lib/adapter/gemini-live-gateway.ts:146

ws.onopen = () => {
  ws.send(JSON.stringify({
    setup: {
      model: `models/${LIVE_MODEL}`,
      generationConfig: {
        responseModalities: ["AUDIO"],
        // …목소리 설정…
      },
      // 처음에 한 번 건네는 말. 레시피가 통째로 여기 들어간다
      systemInstruction: { parts: [{ text: cookingBrief(brief) }] },
      inputAudioTranscription: {},
      outputAudioTranscription: {},
    },
  }));
};

ws.onopen 은 연결이 이어지자마자 한 번 불립니다. 그 자리에서 지시문을 보냅니다. 이후 오가는 말에는 다시 붙이지 않습니다.

유스케이스와 어댑터의 역할이 나뉘어 있습니다. cook-along.ts(유스케이스)는 무엇을 말할지만 정합니다. 웹소켓도 제미나이도 모릅니다. gemini-live-gateway.ts(어댑터)는 어떤 모양으로 보낼지만 압니다. 그래서 나중에 다른 AI로 갈아 끼워도 지시문은 그대로 씁니다.

말투는 어떻게 바뀌나

목소리 고르기 화면에서 고른 말투가 지시문 두 번째 줄에 들어갑니다.

lib/usecase/cook-along.ts:68

const toneAsk: Record<VoiceTone, string> = {
  calm:   "차분하고 또박또박한 말투로, 서두르지 말고 안내한다.",
  bright: "밝고 활기찬 말투로, 짧게 응원하듯 안내한다.",
  soft:   "부드럽고 여유 있는 말투로 안내한다.",
};

말투를 바꾸는 데 모델을 바꾸거나 코드를 고칠 필요가 없습니다. 지시문 한 줄이 달라질 뿐입니다. 프롬프트로 행동을 조절한다는 것이 이런 뜻입니다.

실험 1 — 지시문을 눈으로 보기

lib/adapter/gemini-live-gateway.ts 의 ws.onopen 안, ws.send(...) 바로 위에 이 한 줄을 넣어 보세요.

console.log(cookingBrief(brief));

npm run dev 로 요리 화면에 들어가 개발자 도구(F12) 콘솔을 보면 모델에게 실제로 건네는 글 전체가 찍힙니다. 재료와 순서가 어떻게 글자로 늘어서는지 확인하고 나면 되돌려 놓으세요.

실험 2 — 규칙 한 줄 지워 보기

cook-along.ts 에서 "- 한 번에 한두 문장으로만 답한다…" 줄을 지우고 말을 걸어 보세요. 답이 눈에 띄게 길어집니다. 규칙 한 줄이 실제로 행동을 바꾼다는 것을 확인할 수 있습니다.

실험 3 — 말투를 새로 만들어 보기

toneAsk 의 calm 값을 "사투리로 안내한다." 처럼 바꾸고 요리를 시작해 보세요. 코드는 한 글자도 안 고쳤는데 말투가 달라집니다.

헷갈리기 쉬운 점

지시문은 약속이지 보장이 아닙니다. "절대 대답하지 마라" 라고 적어도 모델이 가끔 대답합니다. 그래서 쿡파일럿은 "다음" 같은 명령을 화면 쪽 코드에서도 따로 처리합니다. 지시문만 믿고 만들면 안 됩니다.

지시문도 토큰을 씁니다. 레시피가 길면 지시문이 길어지고, 그만큼 요금이 붙습니다. 그래도 걸음마다 다시 보내는 것보다는 훨씬 적습니다. 한 번만 보내면 되기 때문입니다.

같은 이름이 API마다 다릅니다. 제미나이는 systemInstruction, OpenAI는 메시지 목록의 role: "system" 입니다. 부르는 이름이 다를 뿐 하는 일은 같습니다. /api/chat 의 RAG 상담은 랭체인의 ChatPromptTemplate 에서 ["system", …] 로 같은 일을 합니다.
