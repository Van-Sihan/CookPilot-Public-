1. 이 프로젝트는 무엇을 하는가

쿡파일럿은 요리하는 동안 말로 레시피를 알려 주는 서비스입니다. 지금 이 저장소에 들어 있는 것은 그 서비스의 웹사이트 두 장입니다.

  • / — 소개 페이지. 무슨 서비스인지 알리고 요금제를 보여 줍니다.
  • /start — 시작 페이지. 구글에서 받은 열쇠(API 키)를 넣는 화면입니다.

아직 없는 것도 알아 두면 코드를 읽을 때 헷갈리지 않습니다. 로그인이 없고, 데이터베이스가 없고, 서버에 무엇을 저장하는 코드도 없습니다. 실제로 음성을 알아듣는 기능도 아직 없습니다. 지금은 화면을 그리는 코드와 열쇠를 받아 브라우저에 담아 두는 코드가 전부입니다.

초보자 핵심 포인트

이 프로젝트는 Next.js 로 만들어졌습니다. Next.js 는 React 라는 도구를 더 쓰기 쉽게 감싼 것이고, React 는 화면을 부품 단위로 쪼개서 만드는 방법입니다. “부품” 을 이 바닥에서는 컴포넌트라고 부릅니다. 예를 들어 화면 맨 위 로고와 메뉴가 들어 있는 부분이 SiteHeader 라는 부품 하나입니다.

4. 1단계 · app/layout.tsx

이 파일의 역할. 주소창에 어떤 주소를 치든, 화면에 나오는 모든 것은 이 파일이 만든 껍데기 안에 들어갑니다. 웹 페이지의 가장 바깥 테두리라고 보면 됩니다. 글꼴을 정하고, 브라우저 탭에 뜨는 제목을 정하고, 배경색을 정합니다.

파일 맨 위부터 봅니다.

네 줄이 각각 하는 일은 이렇습니다.

  • import type { … } from "next" — type 이 붙으면 값이 아니라 “모양”만 가져옵니다. 뒤에서 다시 설명합니다.
  • from "next/font/google" — 구글이 무료로 주는 글꼴을 가져옵니다.
  • from "@/lib/site-content" — @/ 는 “이 프로젝트의 맨 위 폴더부터” 라는 뜻입니다. 파일이 깊은 곳에 있어도 ../../../ 를 세지 않아도 됩니다.
  • import "./globals.css" — 이름 없이 파일만 적었습니다. 가져와서 쓸 것이 아니라 “이 CSS 를 화면에 적용해라” 는 뜻입니다.
알아두면 좋은 것

{ } 안에 이름을 적는 것과 안 적는 것이 다릅니다. import { site } from … 는 그 파일이 내보낸 것들 중 site 라는 이름의 것만 골라 옵니다. 이름이 정확히 같아야 합니다. 오타가 나면 바로 에러가 납니다.

첫째, : Metadata 부분. 콜론 뒤에 적은 것은 타입 입니다. “이 값은 이런 모양이어야 한다” 는 약속입니다. Metadata 모양에 없는 이름을 적으면 실행하기도 전에 빨간 줄이 그어집니다. TypeScript 를 쓰는 이유가 이것입니다.

둘째, 백틱(`)과 ${ }. 따옴표 대신 백틱으로 감싸면 글자 중간에 값을 끼워 넣을 수 있습니다.

화면을 그리는 함수는 “무엇을 그릴지 적어서 돌려줄 뿐” 입니다. 직접 화면에 뭘 칠하지 않습니다. React 가 그 결과를 받아서 진짜 화면으로 바꿔 줍니다. 그래서 return 안에 HTML 처럼 생긴 것이 들어 있습니다. 이 “HTML 처럼 생긴 것” 을 JSX 라고 부릅니다.

className={…} 에서 중괄호가 또 나왔습니다. JSX 안에서 중괄호는 “여기부터는 글자가 아니라 값이다” 라는 신호입니다.

className="hero"        →  hero 라는 글자 그대로
className={hero}         →  hero 라는 이름에 담긴 값
className={`a ${b}`}     →  글자와 값을 섞은 것

{ } — 아까 배운 그대로입니다. “여기부터는 값이다.”

faqs — site-content.ts 에서 가져온 배열 입니다. 배열은 값을 순서대로 여러 개 담아 둔 것이고 대괄호 [ ] 로 씁니다.

.map(…) — “배열의 값을 하나씩 꺼내서, 각각을 다른 것으로 바꾼다” 는 뜻입니다. 질문 다섯 개가 들어 있으면 화면 조각 다섯 개가 나옵니다.

const 숫자들 = [1, 2, 3];

숫자들.map((n) => n * 10)     →  [10, 20, 30]

질문들.map((f) => <details>…</details>)  →  [화면조각, 화면조각, …]

(f) => ( … ) — 화살표가 붙은 이것도 함수입니다. 이름이 없어서 그 자리에서만 쓰고 버리는 함수입니다. f 는 지금 꺼낸 질문 하나를 담는 이름입니다. 이름은 마음대로 지어도 됩니다 — f 대신 질문 이라고 해도 똑같이 돌아갑니다.

헷갈리기 쉬운 점

<details> 와 <summary> — 브라우저가 원래부터 아는 태그입니다. <summary> 를 누르면 나머지가 펼쳐집니다. 이걸 쓰면 여닫는 코드를 한 줄도 안 짜도 됩니다. JavaScript 없이 브라우저가 알아서 합니다.

초보자 핵심 포인트 — 왜 이렇게 번거롭게 할까

그냥 이 파일에서 바로 localStorage.setItem(…) 을 쓰면 안 될까요? 됩니다. 지금 당장은.

하지만 그러면 이 파일이 브라우저가 있어야만 돌아가는 파일이 됩니다. 나중에 “열쇠를 서버에 저장하자” 로 바꾸면 이 파일을 고쳐야 하고, 테스트를 하려 해도 진짜 브라우저가 있어야 합니다.

약속만 적어 두면 이 파일은 브라우저를 몰라도 됩니다. 담는 방법을 바꿔도 이 파일은 한 글자도 안 바뀝니다.

절차 자체

lib/usecase/enter-with-api-key.ts:36 
export function enterWithApiKey(raw: string, store: ApiKeyStore): EnterResult {
  const checked = checkApiKey(raw);

  if (!checked.ok) return { ok: false, reason: checked.problem };

  try {
    store.save(checked.key);
  } catch {
    return { ok: false, reason: "storage" };
  }

  return { ok: true, key: checked.key };
}

받는 값이 두 개입니다.

  • raw — 사용자가 친 글자
  • store — “담아 두는 방법” 자체를 통째로 건네받습니다

두 번째가 낯설 겁니다. 값이 아니라 “할 줄 아는 것” 을 건네받는 것입니다. 이렇게 하면 이 함수는 담는 방법을 몰라도 담을 수 있습니다.

try { } catch { } 는 “해 보고, 안 되면 이렇게 해라” 입니다. 시크릿 창이나 저장을 막아 둔 브라우저에서는 store.save() 가 실패합니다. 그러면 프로그램이 통째로 멈추는 대신 catch 안으로 들어옵니다.

enterWithApiKey("  AIzaSy…  ", store)
        │
        ├─ checkApiKey("  AIzaSy…  ")  →  domain 에게 물어봄
        │         ↓
        │   { ok: true, key: "AIzaSy…" }
        │
        ├─ 통과했으니 store.save(key)   →  adapter 가 실제로 담음
        │         ↓
        │   담기 성공                    담기 실패 (시크릿 창)
        │         ↓                            ↓
        └─ { ok: true, key }          { ok: false, reason: "storage" }
                  ↓                            ↓
              화면이 "저장됨" 으로          화면이 오류 문구를 띄움
알아두면 좋은 것 — 실패를 두 가지로 나눈 이유

reason: "empty" 와 reason: "storage" 는 다른 실패입니다. 전자는 사용자가 고칠 수 있는 것(열쇠를 넣으면 됨), 후자는 브라우저 설정 문제입니다. 뭉뚱그려 “실패했습니다” 라고만 하면 사용자는 무엇을 해야 할지 모릅니다.
