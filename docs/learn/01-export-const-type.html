쿡파일럿 학습 노트 · 01

export, const, type — 파일 하나가 밖으로 무엇을 내놓는가

물어본 것 — “lib/site-content.ts 파일을 보고 있는데 export const, type 등 export 는 뭐고 그 뒤에 오는 건 또 뭐야?”
이 문서를 읽다 생긴 추가 질문 여섯 개(as const 와 const 의 차이, 타입으로 객체를 만드는 법, map·=>·백틱, 빌드하면 타입이 사라진다는 말의 뜻)를 반영해 보강했습니다.

이 문서를 다 읽으면 export const plans: Plan[] = [...] 한 줄을 다섯 조각으로 나눠 읽을 수 있게 됩니다. 각 조각이 무슨 일을 하는지, 그리고 왜 type 으로 쓴 것은 브라우저에 도착하지 않는지 알게 됩니다.

1부 · 기본 문법

export — 이 파일 밖에서도 쓸 수 있게 내놓는다

JavaScript 파일은 기본적으로 자기 안의 것을 밖에 보여주지 않습니다. 문을 닫아 둔 방이라고 생각하면 됩니다. 다른 파일이 가져다 쓰게 하려면 export 를 붙여 내놓아야 합니다.

// 창고.js
export const 사과 = "빨강";   // 밖에서 가져갈 수 있음
const 비밀 = "아무도 모름";     // 이 파일 안에서만

가져가는 쪽은 import 를 씁니다. 중괄호 안에 가져올 이름을 콕 집어 적습니다.

// 주방.js
import { 사과 } from "./창고";

console.log(사과);   // "빨강"
console.log(비밀);   // ✗ 에러 — 내놓지 않았으므로 존재를 모름
알아두면 좋은 것

파일마다 문을 닫아 두는 이유는 이름이 부딪히지 않게 하기 위해서입니다. 파일이 100개인데 모든 것이 다 공개되어 있으면, 어느 파일에서 사과 라는 이름을 쓰는 순간 다른 파일의 사과 를 덮어써 버립니다. 내놓은 것만 오간다는 규칙이 이 사고를 막습니다.

const — 이름을 붙여 값을 담아 둔다

값에 이름을 붙이는 방법은 세 가지입니다.

const a = 1;   // 다시 대입할 수 없음  ← 기본으로 이걸 씁니다
let   b = 1;   // 나중에 b = 2 가능
var   c = 1;   // 옛날 방식. 지금은 쓰지 않습니다

a = 2;   // ✗ 에러
b = 2;   // ✓ 됨
헷갈리기 쉬운 점

const 는 이름에 다른 값을 다시 붙이는 것만 막습니다. 객체 안의 내용은 막지 않습니다.

const 사람 = { 이름: "홍길동" };

사람 = { 이름: "김철수" };   // ✗ 에러 — 이름을 통째로 갈아끼우려 함
사람.이름 = "김철수";        // ✓ 됨! — 안의 내용만 바꾸는 것

정리하면 const 가 지키는 것은 이름표뿐입니다. 상자에 다른 물건을 통째로 갈아 끼우는 것은 막지만, 상자 안을 뒤지는 것은 막지 않습니다.

안의 내용까지 얼려 버리는 방법이 뒤에 나오는 as const 입니다. 이름은 비슷해 보이지만 막는 대상이 다릅니다.

type — 값이 아니라 “모양”을 정한다

여기부터가 TypeScript 입니다. 타입이란 “이 자리에는 이런 모양의 값만 들어올 수 있다”는 약속입니다.

type 사람 = {
  이름: string;      // 문자열이어야 한다
  나이: number;      // 숫자여야 한다
  별명?: string;     // ? 는 "있어도 되고 없어도 된다"
};

이건 값이 아니라 설계도입니다. type 사람 이라고 써도 어디에도 사람이 생기지 않습니다. “앞으로 사람이라고 부를 물건은 이렇게 생겨야 한다”고 정해 둔 것뿐입니다.

그럼 이 설계도로 실제 물건은 어떻게 만드나

두 단계입니다. 설계도를 정하는 것과 그 설계도에 맞는 값을 만드는 것은 별개의 일입니다.

// 1단계 · 설계도를 정한다 (아직 아무것도 안 생김)
type 사람 = {
  이름: string;
  나이: number;
  별명?: string;
};

// 2단계 · 콜론(:)으로 설계도를 걸고 실제 값을 만든다
const 손님: 사람 = {
  이름: "홍길동",
  나이: 30,
};

이름 뒤의 : 사람 이 “이 값은 사람 설계도를 따른다” 는 선언입니다. 이걸 걸어 두면 설계도를 어겼을 때 편집기가 즉시 잡습니다.

const 손님2: 사람 = { 이름: "김철수" };             // ✗ 나이가 없음
const 손님3: 사람 = { 이름: "박영희", 나이: "서른" };  // ✗ 나이가 숫자가 아님
const 손님4: 사람 = { 이름: "이순신", 나이: 40, 키: 180 }; // ✗ 설계도에 없는 칸
알아두면 좋은 것

콜론을 안 붙이고 그냥 const 손님 = { 이름: "홍길동", 나이: 30 } 라고 써도 코드는 돌아갑니다. 다만 아무 검사도 받지 않습니다. 나중에 나이 를 빠뜨려도 아무도 알려 주지 않습니다. 콜론은 “검사해 주세요” 라고 부탁하는 표시라고 생각하면 됩니다.

기억해 둘 기호 네 개

기호뜻예
?있어도 되고 없어도 됨별명?: string
[]배열 (여러 개)string[] 은 문자열 여러 개
|또는 (이 중 하나)"me" | "ai"

2부 · 우리 코드에서는

가장 단순한 모양 — 값만 내놓기

파일 맨 위입니다. 설계도 없이 값만 내놓았습니다.

lib/site-content.ts:8 
export const site = {
  name: "CookPilot",
  nameKo: "쿡파일럿",
  tagline: "손은 요리에, 레시피는 쿡파일럿에",
  description:
    "말로 따라 하는 AI 요리 비서. 젖은 손으로 화면을 만질 일이 없습니다.",
  band: "베타 참여자 모집 중 · 지금은 무료",
} as const;

앞에서 본 const 손님: 사람 = {...} 과 같은 일입니다. 다만 설계도 이름을 따로 만들지 않고, 뒤에 as const 를 붙여 값에서 바로 모양을 뽑았습니다. site 라는 이름의 객체가 실제로 하나 만들어진 것입니다.

이걸 쓰는 쪽을 보면 왜 내놓았는지 알 수 있습니다.

components/site-header.tsx:6 
import { navLinks, site } from "@/lib/site-content";

머리말 컴포넌트가 site 와 navLinks 두 개를 집어 갑니다. 그리고 이렇게 씁니다.

components/site-header.tsx:29 
<span className="name">{site.name}</span>

화면에 “CookPilot” 이라는 글자가 나오는 곳이 여기입니다. 글자를 컴포넌트에 직접 박지 않고 site.name 으로 꺼내 쓰기 때문에, 이름을 바꾸고 싶으면 site-content.ts 한 곳만 고치면 머리말·꼬리말· 메타데이터가 전부 같이 바뀝니다.

@/ 는 무슨 뜻인가

import ... from "@/lib/site-content" 의 @/ 는 이 저장소가 정해 둔 약속으로 “저장소 맨 위에서부터” 라는 뜻입니다. 이 설정은 여기 있습니다.

tsconfig.json:21 
"paths": {
  "@/*": ["./*"]
}

이게 없으면 "../../lib/site-content" 처럼 점을 몇 개 찍어야 하는지 매번 세어야 합니다. 파일을 다른 폴더로 옮기면 그 점의 개수도 전부 바꿔야 하고요.

설계도를 먼저 정한 모양

이제 type 이 붙은 것을 봅니다.

lib/site-content.ts:26 
export type Turn = {
  side: "me" | "ai";
  who: string;
  text: string;
  chip?: string;
  note?: string;
};

Turn 은 “대화 한 마디”의 설계도입니다. 한 줄씩 보면:

  • side: "me" | "ai" — 내 말인지 AI 말인지. 이 둘 말고는 못 씁니다. 화면에서 말풍선을 왼쪽에 놓을지 오른쪽에 놓을지가 이 값으로 갈립니다
  • who, text — 말한 사람 이름과 내용. 반드시 있어야 함
  • chip? — 타이머 알림 같은 딱지. 있는 말풍선도 있고 없는 말풍선도 있어서 ? 를 붙였습니다
  • note? — “말하는 중에 끊어도 됩니다” 같은 곁말

그리고 바로 아래에서 이 설계도를 값에 붙입니다.

lib/site-content.ts:34 
export const heroTalk: Turn[] = [
  { side: "me", who: "나", text: "다음 단계 알려줘" },
  {
    side: "ai",
    who: "쿡파일럿",
    text: "중불로 줄이고 3분만 더 볶아 주세요. 타이머 맞춰 둘게요.",
    chip: "타이머 3:00 시작됨",
  },
  // ... 두 마디 더
];

형광펜 친 Turn[] 이 핵심입니다. “Turn 모양의 것이 여러 개 든 배열” 이라는 뜻입니다. 첫 번째 말풍선에는 chip 이 없고 두 번째에는 있는데, 설계도에서 chip? 로 정해 뒀기 때문에 둘 다 통과합니다.

그래서 무엇이 좋아지는가

화면을 그리는 쪽을 보면 이 설계도가 왜 필요한지 드러납니다.

components/hero.tsx:51 
{heroTalk.map((t, i) => (
  <div key={i} className={`turn ${t.side}`}>
    <span className="who">{t.who}</span>
    <p className="bubble">{t.text}</p>
    {t.chip && (
      <span className="chip">...{t.chip}</span>
    )}
  </div>
))}

이 다섯 줄에 처음 보는 것이 여럿 있습니다. 하나씩 뜯어봅니다.

map — 목록을 하나씩 꺼내 다른 모양으로 바꾼다

map 은 배열을 처음부터 끝까지 훑으면서 하나씩 꺼내 다른 것으로 바꿔 새 배열을 만드는 도구입니다. 개수는 그대로입니다.

const 숫자들 = [1, 2, 3];

const 두배 = 숫자들.map((n) => n * 2);
// 1 을 꺼내 2 로, 2 를 꺼내 4 로, 3 을 꺼내 6 으로
// 결과: [2, 4, 6]

React 가 화면을 반복해서 그리는 방법이 바로 이것입니다. 데이터를 꺼내 HTML 로 바꾸는 것이죠. 말풍선 네 개짜리 배열을 넣으면 화면에 말풍선 네 개가 나옵니다.

heroTalk          → 말풍선 데이터 4개가 든 배열
heroTalk.map(...) → 화면에 그릴 <div> 4개가 든 배열

=> — “이걸 받아서 이걸 내놓아라”

=> 는 화살표 함수입니다. 왼쪽은 받는 것, 오른쪽은 내놓는 것입니다.

(n) => n * 2
 ↑        ↑
받는 것   내놓는 것

우리 코드의 (t, i) => 는 두 개를 받습니다.

이름무엇인가
t이번 바퀴에 꺼낸 말풍선 하나. Turn 모양의 객체
i지금 몇 번째 바퀴인지. 0, 1, 2, 3 …
알아두면 좋은 것

t 와 i 는 우리가 지어 준 임시 이름입니다. 정해진 단어가 아닙니다. (말풍선, 번호) => 라고 써도 똑같이 돌아갑니다. t 는 Turn 의 첫 글자, i 는 index(순번)의 첫 글자를 딴 관습일 뿐입니다.

t. — 꺼낸 것 안에서 값을 집어내기

t 는 말풍선 하나통째입니다. 그 안에서 실제로 쓸 값을 집어내려면 점을 찍습니다.

t          = { side: "ai", who: "쿡파일럿", text: "중불로...", chip: "타이머..." }
t.side     = "ai"
t.who      = "쿡파일럿"
t.text     = "중불로 줄이고 3분만 더 볶아 주세요..."

그래서 <p className="bubble">{t.text}</p> 는 “이번 말풍선의 text 값을 이 자리에 찍어라” 가 됩니다.

백틱과 ${} — 문자열 중간에 값 끼워 넣기

따옴표 대신 백틱(`)으로 감싸면 문자열 안에 ${} 로 값을 끼워 넣을 수 있습니다. 키보드에서 숫자 1 왼쪽, 물결(~) 과 같은 자리입니다.

const 이름 = "쿡파일럿";

"안녕 ${이름}"    // ✗ 그냥 글자. "안녕 ${이름}" 이 그대로 나옴
`안녕 ${이름}`    // ✓ "안녕 쿡파일럿"
헷갈리기 쉬운 점

백틱일 때만 됩니다. 작은따옴표나 큰따옴표로 감싸면 ${...} 가 값으로 바뀌지 않고 글자 그대로 나옵니다. 화면에 이상한 글자가 찍힌다면 따옴표를 잘못 쓴 것은 아닌지 먼저 보세요.

이제 다시 읽어 보기

className={`turn ${t.side}`} 를 보세요. t.side 값이 그대로 CSS 클래스 이름이 됩니다 — turn me 또는 turn ai. 만약 데이터에 side: "mee" 라고 오타를 냈다면 turn mee 라는 없는 클래스가 되어 말풍선이 엉뚱한 자리에 그려집니다.

설계도가 있으면 그 오타를 브라우저를 켜기 전에 편집기가 빨간 줄로 알려 줍니다. 이게 type 을 쓰는 이유의 거의 전부입니다.

파일 사이를 잇는 설계도

파일 6번째 줄에 조금 다른 import 가 있습니다.

lib/site-content.ts:6 
import type { IconName } from "@/components/icons";

import 뒤에 type 이 붙었습니다. “이건 값이 아니라 설계도만 빌려온다” 는 표시입니다. 빌려온 설계도는 여기 쓰입니다.

lib/site-content.ts:53 
export type Feature = {
  n: string;
  icon: IconName;
  title: string;
  body: string;
};

IconName 의 정체는 아이콘 파일에 있습니다.

components/icons.tsx:3 
export type IconName =
  | "mic"  | "play" | "fridge" | "timer" | "scale" | "book"
  | "eye"  | "eye-off" | "key" | "spark";

맨 앞의 | 는 그냥 줄 맞춤용이고, “이 열 개 중 하나” 라는 뜻입니다. 그래서 기능 목록에 없는 아이콘 이름을 적으면 컴파일이 막힙니다.

{ n: "01", icon: "mic",  ... }   // ✓ 있는 아이콘
{ n: "01", icon: "mikc", ... }   // ✗ 오타 — 편집기가 즉시 잡음
알아두면 좋은 것

import type 이라고 명시하는 이유가 하나 더 있습니다. 타입은 빌드하면 완전히 사라집니다. 브라우저는 TypeScript 를 모릅니다. type 이라고 못 박아 두면 “이건 지워도 되는 것”임이 분명해져서, icons.tsx 안의 실제 SVG 그림 코드가 이 파일에 딸려오지 않습니다.

as const — 여기서 굳힌다

파일에는 두 가지 방식이 섞여 있습니다.

export const plans: Plan[] = [...];      // 설계도를 먼저 정한 것
export const faqs = [...] as const;      // 값에서 모양을 뽑는 것

as const 는 두 가지를 한꺼번에 합니다.

첫째, 타입을 좁힙니다. as const 가 없으면 TypeScript 는 name: "CookPilot" 을 보고 “name 은 문자열이구나” 하고 넓게 해석합니다. 붙이면 “name 은 정확히 "CookPilot" 이라는 그 값이다” 로 좁게 굳습니다.

둘째, 내용을 얼립니다. 앞에서 const 는 이름표만 지키고 객체 안은 못 막는다고 했습니다. as const 가 그 안까지 읽기 전용으로 잠급니다.

const A = { 이름: "홍길동" };
A.이름 = "김철수";            // ✓ 됨 — const 는 안을 안 막는다

const B = { 이름: "홍길동" } as const;
B.이름 = "김철수";            // ✗ 에러 — 읽기 전용이라 못 바꾼다
constas const
막는 것이름표를 갈아 끼우기안의 내용까지 바꾸기
타입넓게 (string)좁게 ("CookPilot")
붙는 자리이름 앞값 뒤

둘은 경쟁 관계가 아니라 같이 씁니다. export const site = {...} as const 는 앞뒤로 둘 다 걸어 이름표도 내용도 잠근 것입니다.

고르는 기준은 타입 이름이 다른 곳에서도 필요한가 입니다. Plan 은 이름이 필요해서 type 으로 따로 뽑았고, faqs 는 여기서만 쓰고 끝이라 as const 로 끝냈습니다. 둘 다 맞습니다.

npm run dev

실험 1 · 글 하나 바꿔 보기

lib/site-content.ts 를 열고 tagline 값을 아무 말로 바꿔 저장하세요.

tagline: "손은 요리에, 레시피는 쿡파일럿에",
   ↓
tagline: "오늘 저녁 뭐 먹지",

브라우저 탭 제목이 바뀝니다. tagline 을 쓰는 곳이 한 군데가 아니라는 것도 확인해 보세요 — app/layout.tsx 의 제목·설명과 components/closing.tsx 의 꼬리말이 전부 같이 바뀝니다. 이게 글을 한 파일에 모아 둔 이유입니다.

실험 2 · 일부러 설계도를 어겨 보기

heroTalk 의 첫 번째 말풍선에서 side 값을 "me" 에서 "them" 으로 바꿔 보세요.

{ side: "them", who: "나", text: "다음 단계 알려줘" },

저장하기도 전에 편집기가 빨간 줄을 긋습니다. 마우스를 올리면 이런 말이 나옵니다.

'"them"' 형식은 '"me" | "ai"' 형식에 할당할 수 없습니다.

“them 이라는 값은 me 나 ai 자리에 들어갈 수 없다”는 뜻입니다. 브라우저를 열어보지도 않고 잡힌 것에 주목하세요. 확인했으면 "me" 로 되돌리세요.

실험 3 · 없는 아이콘 이름 써 보기

features 배열의 첫 항목에서 icon: "mic" 을 icon: "microphone" 으로 바꿔 보세요. 역시 빨간 줄이 그어집니다.

이번엔 왜 그런지 따라가 보세요. Feature 설계도의 icon: IconName → 6번째 줄의 import type { IconName } → components/icons.tsx 의 IconName 목록. 파일 두 개를 건너 연결된 약속이 오타를 잡아낸 것입니다. 확인 후 되돌리세요.

실험 4 · map 이 개수만큼 그린다는 것 확인하기

lib/site-content.ts 의 heroTalk 배열에서 마지막 말풍선 하나를 통째로 지워 보세요 ({ side: "ai", ... } 한 덩이).

첫 화면의 대화 카드에서 말풍선이 하나 줄어듭니다. 화면을 고친 적이 없는데도 그렇습니다 — map 이 배열 개수만큼 그리기 때문입니다. 반대로 한 덩이를 복사해 붙이면 늘어납니다. 확인했으면 되돌리세요.

헷갈리기 쉬운 점

타입은 실행되지 않습니다.

빌드란 우리가 쓴 TypeScript 코드를 브라우저가 알아들을 수 있는 순수한 JavaScript 로 바꾸는 과정입니다. (npm run build 가 그 일을 합니다. npm run dev 도 저장할 때마다 같은 일을 몰래 합니다.)

브라우저는 TypeScript 문법을 아예 모릅니다. 그래서 빌드할 때 type 선언, : string 같은 표시, as const 가 전부 지워집니다. “자동으로 사라진다” 는 말은 이 지우는 단계가 있다는 뜻입니다.

아래 두 줄은 우리에게는 다르지만, 브라우저가 받는 것은 완전히 같습니다.

// 우리가 쓴 것
export const plans: Plan[] = [{ name: "맛보기" }];

// 브라우저가 실제로 받는 것
export const plans = [{ name: "맛보기" }];

그래서 타입은 실행 중에 들어오는 값은 검사하지 못합니다. 서버에서 받아온 데이터가 설계도와 다르게 생겼어도 타입은 못 잡습니다. 타입이 지켜 주는 것은 우리가 코드를 쓰는 동안뿐입니다.
